# Parity status

Status of every item in the dash-qt checklist ([research 02 §22](research/02-dash-qt-features.md), `QT-001`…`QT-154`)
and the dashwallet-iOS checklist ([research 03 §4](research/03-ios-features.md), `IOS-001`…`IOS-123`), measured on
`main` at `c3b053b50df60cc75e5ec6555a3e144665746c3e` on `2026-11-18`, against the Tauri desktop app (`apps/desktop`
React renderer over `rust/crates/dw-app` and `rust/crates/dw-engine`).

Statuses:

- **done**: the whole item works end to end in the Tauri app (engine + bound `dw-app` command + `apps/desktop`
  renderer, or native Tauri shell integration), with a test reference (a Rust test, a vitest or Playwright spec, or
  a regtest suite) that covers it.
- **partial**: part of the item works on `main` (for example engine-only awaiting `dw-app` bindings and screens, or
  a sub-feature or platform leg still open or unverified). "What exists" states which part works and what remains.
- **not started**: no implementation on `main` (or an explicit coming-soon placeholder only).
- **not planned**: cut out of desktop scope in [`docs/design/ROADMAP.md`](design/ROADMAP.md) or `docs/PLAN-1.0.md`,
  with the citation.

**Release** names the target version (`0.2`…`1.0`) from `docs/PLAN-1.0.md` where an item is not yet `done` (`—`
when `done`, `not planned`, or not scheduled in `docs/PLAN-1.0.md`).

What backs these statuses on `main`:

- **Rust workspace:** `cd rust && cargo test --workspace` (`dw-app`, `dw-engine`, `dw-vault`, `dw-appdb`,
  `dw-coinjoin`, `dw-governance`, `dw-protx`, `dw-psbt`, `dw-compat`, `dw-console`, `dw-uri`, `dw-units`,
  `dw-message`, `dw-p2p`, `dw-desktop`, and `dwcli`).
- **Renderer & E2E:** `cd apps/desktop && npx vitest run` (view-model, IPC, and fixture contract suites) and
  `npx playwright test` (`apps/desktop/e2e/*.spec.ts` across Chromium and WebKit, plus `apps/desktop/e2e-tauri/`
  WebDriver flows against the live Tauri binary).
- **Regtest:** `regtest/harness/tests/` (`test_l1_sync.py`, `test_l1_send.py`, `test_l2_tools.py`,
  `test_move_mixed.py`, `test_restore.py`) and `regtest/functional/` (`dwd_coinjoin_client.py`,
  `dwd_governance.py`, `dwd_governance_ui.py`, `dwd_masternodes.py`, `dwd_mn_chainlock.py`, `dwd_protx.py`,
  `dwd_shared.py`) against `dashd` v24.

Test references are relative to the repository root. Update this file when a branch lands and keep the summary
table at the bottom in step.
