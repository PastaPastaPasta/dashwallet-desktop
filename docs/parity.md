# Parity status

Status of every item in the dash-qt checklist ([research 02 §22](research/02-dash-qt-features.md), QT-001…154)
and the dashwallet-iOS checklist ([research 03 §4](research/03-ios-features.md), IOS-001…123), measured on
`main` after the M1 integration (m1/mac-ui and m1/cross-ui merged, 2026-10-05).

**Milestone** is the target milestone from DESIGN-opus §5.4/§5.5 (amended by DESIGN.md).
**Status**:

- **done**: the whole item works end to end (engine, view model, and UI in both the macOS app (MacUI)
  and the SwiftCrossUI app (CrossUI)). The test reference names a test that covers it: a view-model,
  runtime or Rust test, an offscreen MacUI render, a regtest L1 test against dashd, or a recorded
  AT-SPI flow on Linux. Desktop equivalents of iOS/dash-qt behaviour are noted in "What exists".
- **partial**: code for part of the item exists and is tested or visible in an app, but part of the
  item is missing. Examples: a later-milestone part, only one of the two apps, engine only with no UI,
  or a dash-qt detail that was not checked. "What exists" says which part. "M1 scope done" means the
  M1 part is complete and the rest belongs to a later milestone.
- **not started**: no code for the item on `main`, or only a contract stub that returns `NotImplemented`.

What backs these statuses on `main`:

- **Rust:** `cd rust && cargo test --workspace`, with dw-engine, dw-vault, dw-appdb, dw-uri, dw-units,
  dw-message and dw-compat.
- **Swift:** `swift test`, with the DashKit, WalletRuntime, WalletFeatures, MacUI screen, DashUIMac
  snapshot and DesignTokens suites. WalletRuntimeTests and WalletFeaturesTests also run on Linux:
  `scripts/linux-docker-test.sh`, headless.
- **Regtest:** the L1 suites `regtest/harness/tests/test_l1_sync.py` and `test_l1_send.py`. They drive
  `dwcli` over SPV against dashd.
- **Linux GUI:** `docs/screenshots/m1/linux/RESULTS.md` records the SwiftCrossUI run under Xvfb.
  AT-SPI drove the demo onboarding and send flows and a live onboarding on the real engine.

Gaps that apply to many rows:

- The five macOS XCUITests (`Apps/macOS/DashWalletUITests`) build, but have not run: macOS
  automation mode needs an interactive authorization.
- No GUI has been exercised against a syncing node or with a real send. Only `dwcli` has, in the
  regtest L1 suites.
- Windows has not been built.

Test references are relative to the repo root; `*` means the whole file.

Update this file when a branch lands: change the status, "What exists" and test reference of each item it
touches, and keep the summary counts in step.
