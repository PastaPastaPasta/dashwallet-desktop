# Dash Wallet Desktop 0.3.0

A desktop Dash wallet for macOS, Windows and Linux with DashPay (usernames and contacts), shielded funds and
Platform addresses on one recovery phrase. 0.3 adds updates from inside the app, a Flatpak for Linux, a read-only
view of your masternodes, legacy Dash Core `wallet.dat` imports, and many fixes to how balances and payments are
shown, above all while a wallet syncs and around CoinJoin.

**This is an early release. No security review has been done. Use small amounts only.** The app says so on
first run.

## What is new in 0.3

- **Updates:** Settings ▸ About ▸ Updates can check for a new version, by hand with "Check for updates" or
  automatically if you turn that on (off by default). An update is downloaded and installed only when you choose to,
  its signature is checked first, and your wallet is locked and saved before Dash Wallet restarts. The AppImage, the
  Windows installer and the macOS app in Applications update themselves; Settings says how to update a Flatpak or a
  .deb.
- **Flatpak:** a Linux Flatpak bundle next to the AppImage and the .deb.
- **While a wallet syncs:**
  - a payment and the balance it makes show within seconds, even on a new wallet that is still syncing, and Home
    says when the balance can still change;
  - a payment that arrives while the wallet syncs is announced, in the bell and on Receive.
- **Balances and payments:**
  - right after you send, the balance no longer counts a spent coin twice until the payment is mined;
  - a transaction someone else relays that spends your coins without your signature no longer takes those coins off
    your balance;
  - a payment already waiting to be mined is found when you add a wallet or new addresses, and a block that pays a
    newly made address is no longer skipped;
  - abandoning a payment you sent now warns that sending the same payment again could pay twice;
  - a payment made with no peers connected says so, instead of "rejected".
- **CoinJoin:**
  - coins mixed in Dash Core (dash-qt) count as mixed after you restore the same recovery phrase: they show in the
    mixed balance with their rounds and can be spent with "Fully mixed funds only (CoinJoin)";
  - a restore or rescan finds CoinJoin coins far down the address list (index 100 and beyond);
  - the balance is right again after a CoinJoin funding step on a restored Dash Core wallet, and "Resolve stuck
    funding" no longer joins mixed coins to unmixed ones.
- **Shielded:** With Shielded on, an idle wallet no longer downloads hundreds of megabytes an hour. Each minute it checks a small proof and syncs only when the shielded pool has changed.
  Send from Shielded has a Max button and says how current the Shielded balance is.
- **Unlock once:** after you unlock with your passphrase, payments up to your spending limit (Settings ▸ Security)
  need no passphrase for five minutes. Larger payments, showing the recovery phrase or keys, changing the passphrase
  and exporting still ask. After the computer sleeps or its clock changes, the next payment asks for the passphrase again, even inside the five minutes after an unlock. 'Ask for every payment' now holds everywhere in the app. If the stored spending limit is missing or does not match the wallet, payments ask for the passphrase until you set the limit again in Settings ▸ Security.
  Lowering the spending limit ends the five minutes at once.
- **Lock screen:** while the wallet is locked, its balance, history and names are no longer in the window behind
  the lock screen.
- **Import:** Settings ▸ Backups ▸ Import reads legacy (Berkeley DB) Dash Core `wallet.dat` files, encrypted or not.
  Import keys keeps the window out of screen captures before it shows the field for a seed or private key.
- **Pay:** Pay ▸ To an address has "Advanced: unsigned transaction (PSBT)" to create a PSBT without opening the
  confirm sheet, and a watch-only wallet sees that it can pay only this way. A PSBT of a Dash special transaction now
  reads back correctly.
- **Masternodes** (Settings ▸ Show Masternodes): a My masternodes tab lists the masternodes whose keys are in this
  wallet and the ones you track, with their status and attributed payouts, read only. Creating a governance proposal
  again with the same name is refused before a second fee is paid.
- **Wallets:** a wallet you create, import or restore opens at the next start, and the last "Open when Dash Wallet
  starts" box in Settings ▸ Wallets stays ticked.
- **DashPay:** a new contact who accepts while your wallet is unlocked finishes setting up without another unlock.
- **Empty screens:** each empty screen of a new wallet has a drawing and, where there is one, the next step to take.
- **Reliability:**
  - a profile picture or an image whose QR code can't be read no longer stops Dash Wallet working;
  - closing a wallet while Dash Wallet reads its coins (coin control, CoinJoin status, a payment) no longer stops
    Dash Wallet working in the cases that were found;
  - switching networks and back can no longer freeze the app;
  - an upgrade interrupted by a crash or power loss no longer leaves the app unable to open its data.
- **Linux:** the window no longer takes about 30 seconds to appear where the desktop portal doesn't answer, and
  Restore options takes a block height on the first click.
- **Looks:** green confirmation text is readable in light mode, and a contact payment on a watch-only wallet keeps
  its buttons.

## Upgrading from 0.2

Install over it. Your wallets and settings stay where they are.

- **After the first start of 0.3, earlier versions cannot open the wallet's data.**
- If you restored a wallet in 0.1 or 0.2 and used CoinJoin with it, or restored it in Dash Core compatibility mode
  or with a custom address lookahead, 0.3 rescans that wallet once from its birth when it first starts, and you can
  send again once the rescan has caught up. Other restored wallets are not rescanned; if CoinJoin funds seem to be
  missing, run Tools ▸ Repair ▸ Rescan ▸ From the wallet's birth.
- Payments that were locked by InstantSend but not yet mined when you upgrade show as unconfirmed until they are
  mined or their lock is seen again. Their value stays in your balance. If they are your only funds, Send may find
  nothing to spend until then; you can still pick them with coin control.
- If an earlier version showed a coin as spent because of a transaction you did not sign, that coin is back in your
  balance after the upgrade, and that transaction is gone from your history.
- **Copies installed before 0.3.0 cannot update themselves to it.** Install 0.3.0 by hand (below). From 0.3.0 on,
  Settings ▸ About can check for updates.
- **Upgrading straight from 0.1: "Include my username in payment requests" (Settings ▸ Privacy) reads off** on every
  wallet, including one where it was on in 0.1. Turn it back on there if you want your username in your payment
  requests.
- **macOS: upgrading has not yet been checked on a real Mac.** After you install 0.3 over an earlier version, macOS
  may ask again for access to the Keychain, or a wallet kept without a passphrase may ask you to unlock it. Keep your
  recovery phrase at hand before upgrading.

## Known limitations

- **No security review.** Do not keep more than you can afford to lose.
- **Not notarized (macOS) and not code-signed (Windows):** the first launch shows a warning.
- **Payments and balances:**
  - If the app quits or crashes while a payment is being sent, that payment may not appear in the history, and the
    coins it spent may still count in the balance, until the network relays it again or it is mined. Before you send
    it again, check whether the first payment went through (for example in a block explorer), or the recipient may be
    paid twice. This also applies to payments to contacts.
  - While a wallet is still syncing, a payment made from another copy of the same wallet can be announced as received
    (for its change). The balance and history are right once the sync finishes.
  - If you restore a wallet after another wallet in the app has synced, payments from before the first wallet was
    created may not appear. After restoring, run Tools ▸ Repair ▸ Reset chain data and resync.
  - In a very rare case, where a payment was locked by InstantSend but a different transaction spending the same
    coins was then confirmed with a ChainLock, this version cannot abandon that payment. The balance may then count
    coins that cannot be spent, or leave out coins that can. To correct it, remove the wallet and restore it from its
    recovery phrase.
- **Abandoned payments:**
  - If one of your wallets abandons a payment to another of your open wallets and that payment still goes through,
    the receiving wallet shows it once it is locked or in a block.
  - If you abandon a payment that still goes through and another device spends its change, this wallet can count
    that change until the other device's payment is in a block.
  - If a payment to you spends an unconfirmed payment Dash Wallet had stopped counting, it may not show until it's
    locked or in a block.
- **Closing a wallet:**
  - Closing a wallet while Dash Wallet is loading or saving its DashPay, Platform or masternode details (for example
    a profile, a username, a contact's details, a Credits top-up or withdrawal, or the masternode list), or while it
    imports a key or watch-only wallet or prepares a wallet's addresses, can stop Dash Wallet working until you
    restart it.
  - Rarely, closing a wallet at the very moment Dash Wallet reads it can still stop Dash Wallet working until you
    restart it.
- **Mixing (CoinJoin) is experimental.**
- **A normal payment or a move to Shielded doesn't use coins that are mixing or mixed.** On a wallet that mixes,
  Pay can say the amount exceeds your balance while Home shows more. To spend fully mixed coins, open Pay ▸
  "Advanced: coins, fee and change" and choose "Fully mixed funds only (CoinJoin)", or move them from the CoinJoin
  page.
- **Shielded:**
  - Shielded availability depends on the network's Platform protocol version. Where the shielded pool is not
    active, the app shows "Shielded is not active on this network yet".
  - After you restart Dash Wallet, Activity shows only part of your Shielded history. Your shielded balance is not
    affected.
  - Right after a move into Shielded, and while a move from Shielded to your Dash wallet is pending, the Shielded
    balance can show 0.00 for a short while.
  - While a shielded payment is still being confirmed, that wallet can't be closed (Settings ▸ Wallets ▸ Close)
    and you can't switch networks. Quitting the app is fine.
  - If storage fails or the computer loses power right after a shielded send, a second payment from that wallet can
    fail visibly. After a restart the app asks you to confirm before sending again.
- **After you move everything from your Platform addresses to your Dash wallet, a small remainder (about 0.003
  DASH) can stay behind.**
- **When you finish an unfinished transfer, the app may take the network's word that it was already used** and clear
  it from the Unfinished transfers card. It does not yet check that answer with a proof.
- **Restoring a wallet created in the iOS app has not yet been tested end to end.**
- **English only.**
- **Masternode screens** (My masternodes, governance and username voting) are behind Settings ▸ Show Masternodes,
  off by default.
- **Flatpak:** a wallet needs a passphrase (the sandbox has no access to the system secret store), and the Flatpak
  keeps its data in its own folder, so it does not see the wallets of an AppImage or .deb install.
- Not yet: Platform ↔ Shielded transfers, shielded-funded usernames, invitation creation, the username marketplace
  (see `docs/PLAN-1.0.md`).

## How 0.3 was tested

Automatically, on the commit this release is built from: the wallet engine's tests on Linux, Windows and macOS,
including opening data folders written by the released 0.1.0 and 0.2.0 and checking that they answer the same; every
screen in Chromium and WebKit on built-in test data, with accessibility checks; the Linux app on its real wallet
engine, opened on a new, empty wallet with no network connection and walked through unlock, Pay, Home, Activity and
Contacts; and `dash:` links opened on all three systems. The installers below were built from that same commit by the
release workflow, which also starts the app once on each system, the Flatpak included.

## Install

- **macOS:** open the dmg, drag Dash Wallet to Applications, then right-click ▸ **Open**, or run
  `xattr -dr com.apple.quarantine "/Applications/Dash Wallet.app"`.
- **Windows:** run the installer; at SmartScreen choose **More info ▸ Run anyway**.
- **Linux:** `chmod +x dash-wallet-0.3.0-linux-x86_64.AppImage && ./dash-wallet-0.3.0-linux-x86_64.AppImage`,
  `sudo apt install ./dash-wallet-0.3.0-linux-amd64.deb`, or
  `flatpak install --user ./dash-wallet-0.3.0-linux-x86_64.flatpak` and then `flatpak run org.dash.wallet.desktop`.

Upgrading from 0.1 or 0.2: install over it. Your wallets and settings stay where they are. Earlier copies cannot
update themselves to 0.3.0, so install it by hand this once; from 0.3.0 on, Settings ▸ About can check for updates.

## Verify

Every file above and `SHA256SUMS` are attested by GitHub (build provenance: built by this repository's release
workflow from the tagged commit). There are no PGP signatures; there is no signing key until 1.0. The updates the
app installs are also signed with the update key built into the app, which it checks before installing.

```sh
gh attestation verify dash-wallet-0.3.0-macos-universal.dmg --repo PastaPastaPasta/dashwallet-desktop
sha256sum -c --ignore-missing SHA256SUMS      # Linux; on macOS: grep <file name> SHA256SUMS | shasum -a 256 -c
```

See `docs/release/verifying.md` in the repository for the details.
