# Dash Wallet Desktop 0.1.0 (pre-release)

A desktop Dash wallet for macOS, Windows and Linux with DashPay (usernames and contacts), shielded funds and
Platform addresses on one recovery phrase.

**This is a pre-release. No security review has been done. Use small amounts only.** The app says so on
first run.

## What is in 0.1

- **Wallet:** create, restore (12/24 words), verify the phrase, passphrase lock, auto-lock, several wallets.
- **Network:** mainnet or testnet, chosen at onboarding and in Settings (a restart applies it); SPV sync.
- **Home:** one balance for everything you can spend, with Core, Shielded and Platform rows.
- **Core:** send and receive (address, QR, `dash:` URI), InstantSend, history, transaction detail, coin
  control, PSBT, sign and verify messages, Export CSV on Activity.
- **Shielded:** balance, receive address, Core → Shielded, send to a shielded address, Shielded → Core.
- **Platform addresses:** balance, activity, and "Move to Dash wallet" to withdraw to Core.
- **Usernames:** register (contested and not), status, main name, profile and avatar, credit top-up and withdrawal.
- **Contacts:** search, requests, contact list, pay a contact, history, notifications. **Invitations:** claim a link.
- **CoinJoin:** mixing start and stop, settings, progress.

## Known limitations

- **No security review.** Do not keep more than you can afford to lose.
- **Shielded availability depends on the network's Platform protocol version.** Where the shielded pool is not
  active (mainnet, until it upgrades), the app shows "Shielded is not active on this network yet".
- **Mixing (CoinJoin) is experimental.**
- **A normal payment or a move to Shielded doesn't use coins that are mixing or mixed.** On a wallet that mixes,
  Pay can say the amount exceeds your balance while Home shows more. To spend fully mixed coins, open Pay ▸
  "Advanced: coins, fee and change" and choose "Fully mixed funds only (CoinJoin)". Coins still being mixed can be
  spent that way once mixing finishes them.
- **Coins mixed in Dash Core (dash-qt) show in your balance after you restore the same recovery phrase, but
  Dash Wallet does not yet count them as mixed.** Don't start mixing on a wallet restored from Dash Core that
  already holds mixed coins. A later update fixes this.
- **After you restart Dash Wallet, Activity shows only part of your Shielded history.** Moves into Shielded and
  moves from Shielded to your Dash wallet don't reappear, and shielded payments you sent reappear without a date.
  Your shielded balance is not affected.
- **Right after a move into Shielded, and while a move from Shielded to your Dash wallet is pending, the Shielded
  balance can show 0.00** for a short while. It corrects itself once the network confirms the move.
- **If the app loses the result of a move from Core to Shielded, the move stays listed as "Checking".** Its amount
  may already be in your shielded balance, but the app can't confirm it yet. You can keep shielding other coins
  meanwhile.
- **While a shielded payment is still being confirmed, that wallet can't be closed** (Settings ▸ Wallets ▸ Close).
  Wait for it to settle. Quitting the app is fine: the payment is picked up again at the next launch.
- **If storage fails or the computer loses power right after a shielded send, a second payment from that wallet can
  fail visibly.** After a restart the app asks you to confirm before sending again; wait for the first payment to
  settle.
- **After you move everything from your Platform addresses to your Dash wallet, a small remainder (about 0.003
  DASH) can stay behind.** It is too small to move yet.
- **Restoring a wallet created in the iOS app has not yet been tested end to end.** The key derivation was compared
  with the iOS and Android code, and a desktop wallet holding Core, Shielded and Platform funds restores in full.
- **English only.**
- **Masternode screens** (governance and username voting) are behind Settings ▸ Show Masternodes, off by default.
- No Platform receive address, no Platform ↔ Shielded transfers, no invitation creation, no username
  marketplace, no fiat, no auto-update (see the plan, `docs/research/gap-2026-10-31/RELEASE-PLAN.md`).
- Not notarized (macOS) and not code-signed (Windows): the first launch shows a warning.

## How 0.1 was tested

On public testnet, with the Linux AppImage built by the release workflow from main:

1. Create a wallet, then restore it in a second data folder: same balance.
2. Receive and send Dash; both appear in Activity with the fee; Export CSV matches.
3. Register a username, add a contact who accepts, pay the contact; both sides show it.
4. Core → Shielded, a shielded payment to another wallet, Shielded → Core; balances exact.
5. Restore a wallet holding Core, Shielded and Platform funds: all three balances, the username and the contact
   return; move Platform funds to Core.
6. Start mixing, see it run, stop it.
7. Windows 11: install, launch and the first screens, by hand. macOS: CI launch check only (the app starts
   and its window opens on GitHub's macOS runner).

## Install

- **macOS:** open the dmg, drag Dash Wallet to Applications, then right-click ▸ **Open**, or run
  `xattr -dr com.apple.quarantine "/Applications/Dash Wallet.app"`.
- **Windows:** run the installer; at SmartScreen choose **More info ▸ Run anyway**.
- **Linux:** `chmod +x dash-wallet-0.1.0-linux-x86_64.AppImage && ./dash-wallet-0.1.0-linux-x86_64.AppImage`, or
  `sudo apt install ./dash-wallet-0.1.0-linux-amd64.deb`.

## Verify

Every file above and `SHA256SUMS` are attested by GitHub (build provenance: built by this repository's release
workflow from the tagged commit). There are no PGP signatures; there is no signing key until 1.0.

```sh
gh attestation verify dash-wallet-0.1.0-macos-universal.dmg --repo PastaPastaPasta/dashwallet-desktop
sha256sum -c --ignore-missing SHA256SUMS      # Linux; on macOS: grep <file name> SHA256SUMS | shasum -a 256 -c
```

See `docs/release/verifying.md` in the repository for the details.
