# BL-187: rust-dashcore pin with Dash Core v24's payloads

Backlog row BL-187. At the old pin (rust-dashcore 8fe0a381), dash-spv's `Peer::receive_message` drops any P2P message it
can't decode: it reports the decode error, skips a byte and resyncs on the next magic. A block carrying a v24 provider
transaction (ProRegTx, ProUpServTx or ProUpRegTx at version 3, or types 10–12) is such a message, so wallet sync
stalls where v24's version 3 is live (testnet since 2026-09-24).

**Result: fixed.** The desktop now pins rust-dashcore `dev` **626c91d1efcc471d2ea06290cadd08ef222aee35** (#1168),
the rev upstream platform pins (73bf039079), through a new platform fork branch `dw/bl187-v24-dashcore` (35e96ca16b,
on `dw/dp3-04b-pool-rotation` 82fb33aff8) that pins the same rev. Every block in Core v24.0.0-rc.3's functional-test
chains that carries one of these payloads decodes, re-encodes byte for byte, and reaches dash-spv's `receive_message`.
So does a block whose special transaction has a type no build knows, or a known type in a layout no build knows (both
kept raw). At the old pin, 7 of those 9 blocks fail and an eighth is misread.

| D6 | **#1144: `signer::CompactSignature` is gone; `MessageSignature::new(sig, true).serialize()` and `MessageSignature::from_slice(..).signature` replace it.** Same 65 bytes (header `27 + 4 + recid`). At the old pin nothing was truncated at all, so this is strictly better. The gap is upstream's; no desktop workaround (follow-up). |
