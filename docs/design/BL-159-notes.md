# BL-159 notes: the flaky lease test `r1_f2_an_artifact_seen_sent_during_its_resolution_keeps_its_marker`

Status: a test race. The final journal and fence state are correct in every interleaving found, so the engine is unchanged.
The tests changed, and E0-04 §7.6 gained one sentence describing behaviour the code already had.

| Row | Decision |
|---|---|
| D-1 | **Root cause.** `finish(NotSent)` of a marked row-less artifact takes two J steps. J1 (`finish` → `start_settle`) makes the entry `Resolving`. J2 (`resolve_not_sent`) checks `keep_sent`, notes `Superseding` and begins the `NotSent` write. Between them, J is free: J1's effects run (its lease's `LeaseChanged` emit). The test waited for `Resolving` (`until(resolving)`, polled every 1 ms), so on a starved runner it could call `note_seen` in that gap. The sighting begins the bundled `Sent` row (stalled 300 ms). Then J2 finds the artifact sent (`keep_sent`), writes nothing and returns, so `finish` returns `MaybeOut` at once. At that moment the journal holds only `[Marked(s)]`: one standing marker with `sent == false`. `until(\|\| j.load().1.len() == 1)` held immediately, and `assert!(j.load().1[0].sent)` failed. In the usual order the `NotSent` row lands first (`[Marked, NotSent]`, no standing row), so the count reached 1 only when the `Sent` row landed. The row count was a proxy that is also true before any resolution row exists. |
| D-2 | **Second symptom of the same proxy.** Under load the `Sent` row can be on disk (the count holds, `sent` is true) before the write's own J step marks the evidence `Durable`. The test's final `admit` then correctly defers on the `Committing` evidence (DEC-154: copies wait for the `Sent` row), and `resend` panicked with `expected Resend, got Deferred` (tests.rs:313). It was seen 2 times in 600 loaded runs. It was not seen on CI, but the cause is the same. |
| D-3 | **Classification: test race, not a code race.** In the D-1 interleaving the end state is what DEC-154 asks for: the `Sent` row lands as `[Marked(s), Sent]`, the marker stands with `sent`, the charge stays spent (`(1_000, 10)`), the only resolution event is `Sent`, and a copy resends once the evidence is durable. No `NotSent` row is written, which E0-04 §7.6 now says. Evidence: with a temporary 20 ms sleep between the two J steps (local and uncommitted), the old test body failed 10 of 10 runs with exactly the CI assertion, and the new test of this interleaving passed 10 of 10. No ledger semantics changed. |
| D-4 | **Fix (tests only).** (a) The existing test now holds the `NotSent` write in the journal (`FakeJournal::hold_not_sent`, the pattern of `hold_signed_lock`), sights the artifact while it is held, then releases it. It always exercises its titled interleaving, with no wall-clock window. It ends on the fence's acknowledgement, `evidence_mark == Durable`, which follows the row reaching disk and is what hands off the copy. (b) A new test, `r1_f2_an_artifact_seen_sent_before_its_resolution_is_written_keeps_its_marker`, pins the D-1 interleaving deterministically. A test sink (`HoldingSink`) holds `finish` in J1's `LeaseChanged` emit, i.e. after `Resolving` and before J2. The test sights the artifact, releases `finish`, and asserts the same end state plus "no `NotSent` row was written". While `finish` is held, it also asserts `Resolving` and no `Superseding`, so the test fails at that line if J1 stops emitting `LeaseChanged`, instead of passing through another interleaving. No sleep was added and no timeout widened. The 300 ms stall was removed from the existing test, so the two rows may land in either order. Both orders end the same way, because a `Sent` row is final whatever its position (DEC-154, `marker_stands`). |
| D-5 | **Each test guards its own branch.** Two temporary env-gated mutations were run once, then removed. Skipping J2's first `keep_sent` (the write goes ahead) fails only the new test ("no NotSent row was written"). Skipping the `keep_sent` after the write (the artifact settles `DefinitelyUnsent` and is refunded) fails only the existing test (`finish` ≠ `MaybeOut`). These ran against the first version of the existing test (D-6). They were not re-run after the hold replaced its trigger. The interleaving is unchanged: a sighting during the write, then J3 without `keep_sent` settles `DefinitelyUnsent`. |
| D-6 | **Wall-clock window removed (r2 of this branch).** The first version triggered on `LogEvent::Superseding` and kept the 300 ms stall, so `note_seen` had to run within the stalled write. Under the D-9 load it then failed 1 time in 600 with `finish` = `DefinitelyUnsent` (bd10edc7 tests.rs:3019): the test task was starved past the write, and the sighting came after the settlement. That is the same window the old trigger had. The `NotSent` write is now held instead (D-4 a), so the test has no stall at all. The R2 tests (`r2_seen_during_resolution`) pin the same interleaving against the file-backed journal. |
| D-7 | **Siblings checked** (tests.rs, `stall_ms` / `until`): `a_copy_of_a_step_artifact_waits_for_every_marker` (2186), the 1184 Lock copy test, `a_failed_step_write_hands_off_no_copy_until_it_is_repaired`, `r1_f1_a_copy_owes_a_marker_begun_before_it_joined`, `r1_f2_a_marker_write_never_settles_a_sent_artifact` (already waits for `Durable` before its copy), `r1_f2_a_blocked_settlement_lands_when_the_write_fails` and `r1_f2_a_blocked_slot_settlement_lands_when_the_write_fails` (they wait for `dispatch_status == NotSent`, which follows the row), `r2_f1_sent_evidence_survives_a_reopen` (its row count is the real end condition, since it then reopens the file), `r2_l1_closing_the_journal_waits_for_its_writes` and `o5_closing_the_journal_waits_for_a_register_write`. None polls a journal row count as an end state, so none shares the proxy. Not changed. Review O-4 noted that three of them snapshot a state within a 300 ms write window instead: `r2_l1` asserts evidence `Committing` right after `note_seen`, `r1_f1` asserts `committing("u")` after `poll_once`, and `r1_f2_a_blocked_settlement_lands_when_the_write_fails` expects the settlement blocked by a write that is still running. That is D-6's wall-clock class, listed in D-8. |
| D-8 | **Different pattern, left alone.** `a_dropped_admit_or_register_keeps_the_fence_consistent` uses fixed `sleep(50 ms)` / `sleep(250 ms)` around a 150 ms stall, then asserts on the journal and resends. That is a plain wall-clock dependency, not a sampled transient, and it has not failed on CI. The three D-7 window tests are in the same class. Follow-up only: if any of them flakes, replace its stall with a held write, as `FakeJournal::hold_signed_lock` does. |
| D-9 | **Reproduction.** Unmodified `main` 53a78fb1, debug test binary, the test alone (`--exact --test-threads=1`). 24 loops in parallel, pinned with `taskset` to 2 CPUs that also run 4 busy-loop hogs. 704 runs without hogs (1 or 2 CPUs) never failed: the 300 ms stalls left the CPUs idle, so the threads were not preempted. With hogs: 1 failure at tests.rs:2979 (the CI assertion) in 2,400 runs, and the D-2 symptom 2 times in 600. CI hits it more often: run 38687350378's engine tests took 1419 s. |
| D-10 | **Acceptance.** Same D-9 setup, on the final test binary (fcc4807a): the existing test passed 2,400 of 2,400 and the new test 600 of 600, with no failures. The first version (bd10edc7) had passed 2,400 and 600 at first, then failed once in a further 600 (D-6). |
